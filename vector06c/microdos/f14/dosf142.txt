	1. Работа с клавиатурой
	■■■■■■■■■■■■■■■■■■■■■■■

    В отличие от BIOS 3.11 клавиша РУС/ЛАТ используется по прямому  наз-
начению - для переключения режимов РУС/ЛАТ с индикацией, а клавиша  F5 - 
как CAPS SHIFT (т.е. для постоянного переключения пропис-ных  и строчных 
букв, в отличии от СС - временное переключение верхнего и нижнего регис-
тров).

    Дополнительная клавиатура выполнена многофункциональной и код нажатой 
клавиши зависит устанавливаемого пользователем режима дополнительной кла-
виатуры, а также клавиш <УС> и <СС>. Это сделано для стандартизации инте-
рфейса с прикладными программами. Помимо этого пользователь имеет возмож-
ность выбора режима вывода на консоль в КОИ-( или КОИ-7.

    Переключение режимов происходит при нажатии клавиши <СС> совместно  с 
клавишами  <F1>, <F2>, <F3> и <F4>, а выбор режима КОИ-7/КОИ-8 - с клави-
шами <F5> и <АР2>.
	
	<СС>+<F1>	- обычная клавиатура BIOS 3.1
	<СС>+<F2>	- клавиатура для редактора QWERTY
	<СС>+<F3>	- клавиатура для редактора JCUKEN
	<СС>+<F4>	- клавиатура пользователя, вначале - 
			  обычная клавиатура BIOS 3.1


	<СС>+<F5>	- КОИ-7
	<СС>+<АР2>	- КОИ-8


	Список дополнительной клавиатуры:

    <ТАБ>, <ПС>, <ВК>, <ЗБ>, <F1> ... <F5>, <HOME>, <СТР>,
    <клавиши-стрелки>

	2. Список новых и модифицированных команд
	■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■

    Изменения  в  BIOS 3.11  вносились для большего удобства работы 
одновременно в нескольких областях пользователя на дисках Микро-ДОС 
(см. команду U операционной системы). Кроме того, была введена воз-
можность перенастройки дополнительной клавиатуры для работы в среде 
нескольких редакторов (клавиатура QUERTY и JCUKEN).
    Особо следует упомянуть модификацию команды переименования фай-
лов, которая в данной версии допускает групповое переименование  (в 
исходном  BIOS  3.11  допускается переименование только ОДНОГО явно 
заданного файла).

    Список команд:
	0 X K<CR>............ выбор дополн. клавиатуры
	5 file0 file1<CR> ... переименование файла(файлов)
	6 file X<CR> ........ сброс признака X
	7 file X<CR> ........ установка признака X
	9 ud[,ud]<CR> ....... указание пути поиска файлов
	9 ?<CR> ............. просмотр пути поиска файлов 
	9 S<CR> ............. обычный путь поиска (USER 0, затем 
				диск A)
	9<CR> ............... поиск файлов только в тек. пользова-
				теле

	3.2. Переименование файлов
	■■■■■■■■■■■■■■■■■■■■■■■■■■

    В BIOS 3.11 для переименования ОДНОГО файла используется команда 5

	5 file0 file1<CR>

где file0 - имя.расш исх.файла, а file1 - имя.расш рез.файла. Например:

	5 TEST.DOC TESST.LST<CR>

    В BIOS F.14 допускается групповое переименование файлов:

	5 TEST*.D?C LIST*.L?T<CR>

Основным требованием является совпадение знамов * и ? в file0 и file1.
Команда выводит на консоль имена исх. и переименованных файлов, например:

	1A>5 *.ASM *.A<CR>
	TEST    .ASM  -->  TEST    .A
	ADV     .ASM  -->  ADV     .A


	3.3. Установка и сброс признаков файла
	■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■

    В  BIOS  F.14  введены  команды  групповой  установки  и  сброса 
спец.признаков в имени файла (системный, только для чтения, архивный 
и признаки пользователя 1...4). Для установки признаков используется 
команда 7:

	7 file X<CR>

где file - имя.расш (можно использовать знаки * и ?), а


				- 7 -

      X		   признак
    ■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■
      S		системный файл
      R		только для чтения
      A		архивный файл
    1...4	признаки пользователя

    Для сбрасывания соответствующего признака используется команда 6 с
аналогичным команде 7 синтаксисом:

	6 file X<CR>

    Обе команды выводят на консоль имена обрабатываемых файлов, например:

	2C>7 *.ASM S<CR>
	*TEST    .ASM
	*ADV     .ASM

	2C>6 *.* S<CR>
	 ALL
	*TEST    .ASM
	 TEST    .COM
	*ADV     .ASM

    Здесь * - отмечает файлы, признаки которых команды 6 или 7 действи-
тельно изменили.

	3.4. Указание пути поиска файлов
	■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■

    BDOS Микро-ДОС, если требуемый файл не найден на текущем  диске  в 
заданном пользователе, пытается найти системный файл с заданным именем 
сначала на текущем диске в области пользователя 0, а затем на  диске A 
в области пользователя 0.

    BIOS F.14 изменяет BDOS так,чтобы можно было указывать другой кро-
ме стандартного путь поиска файлов. Для этого используется команда 9:

				- 8 -

	9 ud[,ud]<CR>

где ud - номер пользователя и диск. При этом диск Z - означает текущий 
диск. Допускается не более 8 дополнительных областей поиска.  Например:

	9 1Z,15A,0B,S<CR>

    Файл будет разыскиваться последовательно в пользователе  1  текущего 
диска, пользователе 15 диска A и пользователе 0 диска B. Затем поиск бу-
дет продолжен по стандартному пути:  в пользователе 0 текущего  диска  и 
диска А. По команде:

	9 15B<CR>

поиск будет производиться тоько в 15 пользователе диска Б.

    Установить только стандартный путь поиска можно командой:

	9 S<CR>

    Просмотреть текущий дополнительный путь поиска можно по команде:

	9 ?<CR>

    Запретить поиск файла вне тек. области пользователя на тек. диске 
можно командой:

	9<CR>

				- 9 -


    ПРИМЕЧАНИЕ: Если искомый файл не находится в текущей области поль-
зователя на текущем диске, то для того, чтобы он был найден, у него должен 
быть устатовлен признак СИСТЕМНЫЙ ФАЙЛ. (См. раздел 3.2).

    ЗАМЕЧАНИЕ: в BDOS Микро-ДОС 3.1 разработчиками была допущена ошибка, в 
результате которой при попытке создать файл прямого доступа размером более 
16К, вне зависимости от того, в каком пользователе этот файл первоначально 
создавался, след. экстент открывался в пользователе с номером 0. Начиная с 
BIOS F.14, эта ошибка исправляется при инициализации BIOS.

    Указание пути поиска файлов может быть использовано для нескольких целей.
Например, из-за некоторой несовместимости CP/M 3.1 и Микро-ДОС 3.1 передача 
с помощью программы PIP.COM файла с признаком "системный" из области пользо-
вателя 0 диска А (с использованием ключа R), приводит к сообщению

A>PIP C:=A:REBUS.COM[R]

BDOS ERROR ON A:REBUS.COM SYSTEM FILE
O= 19   PC= 08C2H

		3.5. Использование команд 0...9 в программе

   Область BIOS F.14 начинается с адреса 0DB00H и содержит вначале вектор 
переходов:

	0DB00H	JMP	INIBIOS		; инициализация BIOS
	0DB03H	JMP	INIBIOS
	0DB06H	JMP	GRSTATUS	; статус консоли,принтера и доп.устр.
	0DB09H	JMP	GRINPUT		; ввод с консоли и доп. устройств
	0DB0CH	JMP	GROUTPUT	; вывод на консоль,принтер и доп.устр.
	0DB0FH	JMP	ADRDPH		; адрес DPH области для дисковода
	0DB12H	JMP	RDWRDISK	; обмен с дисковыми устройствами
	0DB15H	JMP	ADRMESSAGE	; адрес начала таблицы адресов текст.
					;   сообщений
	0DB18H	JMP	USERCOMMAND	; обработка команд пользователя

    Для вызова из программы пользователя любой команды Микро-ДОС 0...9 надо 
вызвать подпрограмму USERCOMMAND, передав ей в рег.<A> номер команды, напри-
мер:

	MVI	A,6
	CALL	0DB18H

    Предварительно необходимо подготовить в FCB1 (5CH...) имя файла (возможно, 
содержащее * или ?), у которого необходимо сброить признак, записанный в ячей-
ке 6CH ('S', 'R', 'A' или '1'..'4'). Для получения  дополнительной  информации 
см. 5.

		4. Отличия версий 3.11 и F.14, FP.14
		------------------------------------

    Для размещения BIOS F.14 используется область таблиц исходного BIOS 3.11, 
поэтому размер транзитной области пользователя не уменьшается.
    В версии BIOS FP.14  изменено расположение секторов на квазидиске, что 
делает ее частично несовместимой со всеми предыдущими версиями  Микро-ДОС. 
Начиная с версии 3.0 использовалось след. распределение памяти в  банке  0 
квазидиска:

		0F000H...0FFFFH - область контр. сумм квазидиска
		0E000H...0EFFFH - нач. дорожки квазидиска
		0A000H...0DFFFH - замещали ОЗУ экрана
		00000H...09FFFH - продолжение дорожек квазидиска

В версии BIOS FP.14 банк 3 квазидиска используется след образом:

		0E000H...0FFFFH - замещает ОЗУ ЭВМ
		0A000H...0DFFFH - замещает ОЗУ экрана
		08000H...09FFFH - замещает ОЗУ ЭВМ

В банке 0 квазидиска зона 0A000H..0DFFFH используется для размещения послед-
них дорожек, а зоны 8000H...9FFFH и 0E000H...0FFFFH - используются стандарт-
ным образом , что приводит к уменьшению об'ема квазидиска на 16К, но  сохра-
няет совместимость с начальным загрузчиком.
    Эти изменения вызваны требованием упростить обмен между ОЗУ ЭВМ  и  ква-
зидиска в программах,где требуется работа с 32К экранами и сохранением среды 
Микро-ДОС.
