Я работаю в сельской школе — веду компьютерный кружок.
Поскольку наша школа не может приобрести какой-либо компьютер, я проводил занятия на своем личном ПК "Вектор-06Ц". Конечно, "Вектор" — не IBM PC, но ребята и этим довольны. Мои друзья-вектористы по заочному компьютерному клубу, прослышав о наших трудностях, взялись помочь нам. Теперь у нас в кабинете свой (постоянный) ПК "Вектор-06Ц", и даже с дисководом.

Обычно после занятий ученики играют в разные игры на ПК. И вот тут-то ребятишки прямо "дерутся" из-за места за компьютером, поскольку ПК — один. Вообще-то, можно поставить еще один "Вектор", но загружать программы с магнитофона — дело нудное. Подключить же к одному НГМД два ПК нельзя. Но все-таки в какой-то мере разрешить загрузку программ с НГМД во второй ПК нам удалось, правда, только непосредственно через первый. Суть найденного нами решения проста. Поскольку один ПК оснащен НГМД и работает с DOS, то рабочий процесс заключается в следующем — программа загружается с диска в один ПК, а затем передается на другой через параллельный порт (на "Векторе" это принтерный разъем "ПУ"). Метод передачи данных через параллельный порт мы посчитали самым быстрым, удобным и доступным (и никакой "локалки"). Была разработана схема соединения двух компьютеров и написаны специальные программы для этого. Данную разработку мы назвали "VECTOR DATA — OUT/INT". Подробное описание уже было опубликовано в бюллетене ИНВЕКТОР-клуба (№16), но его тираж очень мал, поэтому я и предлагаю эту статью для широкого круга читателей.

Схема соединения ПК "Вектор" через разъемы "ПУ" очень проста и содержит всего 11...12 проводов (в зависимости от числа "нулевых" проводов).

Порт 07 (канал РА) обоих ПК используется для передачи данных, и значит, соединяются эти порты параллельно — разряд в разряд:

```
A02 <> A02 — data07
A03 <> A03 — data06
A04 <> A04 — data05
A05 <> A05 — data04
A06 <> A06 — data03
A07 <> A07 — data02
A08 <> A08 — data01
A09 <> A09 — data00

A10, C01 <> A10, C01 — 0 В
```

Две линии порта 05 (регистр РС) используются для передачи/приема сигнальных битов готовности и синхронизации и соединяются "перекрестно":

```
C02 <> C09
C09 <> C02
```

Вот и вся схема соединения.

Соединительные провода должны иметь сечение не менее 0,08 мм и волновое сопротивление порядка 60...150 Ом.

Если применить плоский кабель (20 жил), чередуя все сигнальные линии с линией "0 В" (как в шлейфе НГМД), то длина шлейфа может превысить 0,5 м. При использовании "витой пары", когда каждый сигнальный провод скручен с "общим" проводом, плюс все эти пары скручены в один пучок — длина кабеля может быть и больше.

Значительно увеличить длину кабеля можно, если весь этот жгут заэкранировать, соединив экран с обеих сторон с линией "0 В" (контакты разъема A10, C01).

Для передачи данных (с одного ПК на другой) через порт ПУ был написан программный модуль, состоящий из двух отдельных программ. Программа-приемник называется VD-INP, а программа-передатчик — VD-OUT.

Для работы необходимы два "Вектора", один из которых (ПК-передатчик) должен быть оснащен дисковым устройством и работать под управлением DOS, другой (ПК-приемник) не требует никакой дополнительной периферии.

Первоначально с первого ПК нужно с помощью утилиты SAVEROM записать на второй ПК через магнитофонные разъемы (с помощью кабеля) файл VD-INP/ROM (это всего 3 блока). Запустив программу, включаем режим ожидания (что подтверждается сообщением на экране). А затем с помощью программы VD-OUT.COM передаем с диска ПК-передатчиком любую программу на ПК-приемник. Название данной программы указывается в командной строке в обычном формате. Например, вам нужно загрузить на второй ПК игру PUTUP. Командная строка в MicroDOS будет выглядеть так:

```
> VD-OUT PUTUP.COM
```

После нажатия <ВК> игра будет перегоняться на другой ПК, который известит вас об этом сообщением "ЧИТАЮ".

Данная операция протекает следующим образом. Вначале передается шифр, означающий НАЧАЛО передачи, затем два байта — размер файла, потом контрольная сумма и уж потом — сам файл, по окончании которого передача прекращается, и происходит выход в DOS.

Аналогично производится и прием. Пока не поступит шифр НАЧАЛО, чтение не начнется. При получении шифра НАЧАЛО, считается размер данного файла и КС, и только потом принимается тело файла прямо в ОЗУ (по реальным адресам). Одновременно на экране отображается ход процесса. При считывании указанного объема данных чтение прекращается, высчитывается контрольная сумма, и, если нет ошибок, загруженная программа автоматически запускается. Если КС не совпадают, загорается индикатор "РУС" и выводится соответствующаяся. надпись. Это значит, что вы можете нажать кнопку <УС> и повторить загрузку. А можно нажать кнопку <РУС/ЛАТ> и запустить игру. Если несовпадающий байт не критичен — игра полностью работоспособна.

При запуске игры программа VD-INP уничтожается. Поэтому для загрузки очередной игры необходимо снова загрузить VD-INP и все повторить.

Фактически, на второй ПК можно передать любой файл, но работать будут только самозапускающиеся программы (в машинных кодах).

Рассмотрим алгоритм передачи/приема байта. Данные передаются/принимаются через порт 07, для чего в передающем ПК порт 07 настраивается на вывод (как для принтера, команды MVI A,81H: OUT 04), а в ПК-приемнике — на ввод (как для джойстика, команды MVI A,83H: OUT 04). Порт 05 работает как обычно — младшая тетрада на ввод, старшая на вывод, в связи с чем и применено "перекрестное соединение" линий синхронизации и готовности. Через порт 05 ПК обмениваются т.н. стробирующими сигналами ("0" или "1"), причем каждый из них выдает сигнальный бит в разряд 07 (порт 05), а читает разряд 00. Кстати, изменение разрядов порта 05 производится портом 04. Логическая "1" от ПК-передатчика означает ПЕРЕДАЧУ БАЙТА В ПОРТ, а логический "0" — ГОТОВНОСТЬ/ОЖИДАНИЕ. Логическая "1" от ПК-приемника означает ГОТОВНОСТЬ/ЧТЕНИЕ, а логический "0" — ЗАНЯТО.

Протокол работы выглядит следующим образом. ПК-передатчик ожидает сигнал готовности от ПК-приемника. Получив этот сигнал, он выдает свой сигнал о передаче и посылает байт данных в порт, после чего ожидает сигнал о приеме данных.

Получив сигнал-подтверждение о приеме, ПК-передатчик сбрасывает свой сигнал передачи и возвращается из подпрограммы (п/п) за следующим байтом, после чего все начинается сначала.

ПК-приемник, послав сигнал о готовности, ожидает сигнал передачи, получив который, он считывает байт данных, сбрасывает свой сигнал и переносит данные в ОЗУ. После этого снова возвращается в п/п, и все повторяется.

Ниже приводятся ассемблерные тексты п/п (драйверов) приема/передачи байта данных (по отдельности).

П/программа передачи байта

```
; Перед входом в п/п байт данных для передачи заносится в
; регистр С

DTOUT: IN 05         ; проверяем разряд 00 порта 05
       RAR           ; (в цикле "пока 0")
       JNC DTOUT     ; если 1, то переписываем из
       MOV A,C       ; регистра С в А
       OUT 07        ; байт данных и записываем его в порт 07,
       MVI A,0FH     ; а разряд 07 порта 05 устанавливаем в "1"
       OUT 04
COUT:  IN 05         ; и ждем сброса
       RAR
       JC COUT       ; если в разряде 00 порта 05 — "0"
       MVI A,0EH     ; то сбрасываем разряд 07
       OUT 04        ; того же порта в "0"
       RET           ; и выходим
```

П/программа приема байта

```
DTINP: IN 05         ; проверяем занятость передатчика
       RAR
       JC DTINP      ; если в разряде 00 порта 05 — "0", то
       MVI A,0FH     ; устанавливаем разряд 07 того же порта
                     в "1" и
       OUT 04
CINP:  IN 05         ; ждем появления "1" в разряде 00
       RAR
       JNC CINP
       IN 07         ; если пришла "1", то считываем байт из
                     ; порта 07
       MOV C,A       ; переносим его в регистр С и
       MVI A,0EH     ; сбрасываем "0" в разряд 07 порта 05
       OUT 04
       RET           ; и выходим из п/п
```

В данных п/п используются только регистры А и С (причем С — для обмена данными с п/п).

Можно было бы реализовать в данных п/п проверку подтверждения правильности приема байта, но этого не требуется, поскольку программные сбои в данном алгоритме исключены (хотя возможны аппаратные — из-за наводок в соединительном кабеле).

Можно написать аналогичную "системку" для нескольких ПК с фиксированным выбором любого из них, но пока в этом нет потребности.

Примечания к расшифровке:

- В листингах константы напечатаны как `0FH` (установка разряда 07 порта 05) и `0EH` (сброс разряда 07) — это управляющие слова битовых операций, выдаваемые в регистр порта 04; в скане шрифт листинга слитный, значения прочитаны посимвольно.
- В оригинале набрано "соответствующаяся." (так в журнале); кнопка набрана как `<УС>`, по смыслу это, скорее всего, `<ПУСК>`.
- На с.40 после окончания статьи начинается материал «Оптимизация загрузки констант в регистры» (процессор Z80, к ПК "Вектор" отношения не имеет), здесь не расшифровывается. Иллюстраций в статье нет.
